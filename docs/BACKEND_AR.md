# أساس قاعدة بيانات PalEdu — غير منشور

هذه الملفات تأسيسية فقط؛ لا يوجد حتى الآن مشروع Supabase أو بيانات طلاب مرفوعة.
سيبقى التطبيق الحالي بدون حسابات وبلا جمع بيانات شخصية عبر الإنترنت.

## التصميم المقترح

- حزم المحتوى الثابت وملفات PDF والفيديو تُقدّم من Object Storage + CDN.
- قاعدة PostgreSQL تحتفظ ببيانات الطلاب المصرح بها، والمراجعات المنشورة فقط.
- RLS على جميع الجداول المرئية، وقصر قراءة تقدم الطالب على صاحبه.
- صلاحية نشر المناهج مخصصة لخدمة خلفية مدققة؛ لا تُخزَّن مفاتيح الخدمة في Flutter.
- لا يُقبل محتوى رسمي إلا بعد الترخيص والمراجعة التربوية.
- بيانات القاصرين تتطلب سياسة خصوصية وتوثيق موافقات مناسبة.

## القدرة الاستيعابية

الهدف مئات الآلاف من المستخدمين المسجلين وليس ضمان تزامنهم.
ينبغي قياس عدد المستخدمين النشطين في الذروة، نسبة استجابة CDN،
استهلاك البيانات، زمن الاستجابة P95/P99، الأخطاء وأداء قاعدة البيانات.
أداة k6 في performance/staging_content.js لا تختبر الإنتاج؛ يمكن تشغيلها
على خادم staging حقيقي بعد توفره.

## قبل تشغيل migration

مراجعة أمنية، اختبار سياسات RLS بمستخدمين مستقلين، نسخ احتياطي،
سياسات إدارة وسائط وترخيص، اختبار صلاحية المراجعين، وإجراءات حذف البيانات.
